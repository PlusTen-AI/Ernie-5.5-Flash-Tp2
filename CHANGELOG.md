## 0.6.0
- concurrency up to 16 requests (server.slots 1 … 16, default still 4): every step carries its kind, set by its caller — a prompt chunk is prefill, decode / verify / draft steps are decode (core/step_kind.h, `Engine::step(…, prefill)`) — and the kind, never M alone, chooses the kernels (a 1-row prompt chunk after a restore takes the prefill kernels, a 128-row verify the decode ones); the DSpark draft head (P081's NVFP4 lm_head) called in 64-row pieces, bitwise at B ≥ 10; nothing else in the engine was fixed at 4 (16 sequences a round, logit rows slots × 8)
- verify / draft steps of 5–16 sequences, bitwise: P066's one-launch decode MoE at 33 … 64 rows P190 (×1.05 at 40–64 rows), P078's column-half split weights at 17 … 64 rows P191, mHC one CTA a chunk at 33 … 64 rows P192 (post + pre a step 4.22 → 2.71 ms at 64 rows, 2.86 → 2.18 at 48), the router / compressor pair kernel at 33 … 64 rows P193 (47 → 22 µs at 40 rows, 56 → 28 at 64); MoE at 65 … 128 rows P194 measured, off (×1.07 at 65 rows, ×0.94 at 128)
- FP8 block GEMM at 33 … 128 rows P200, bitwise: P030's kernel with token tiles of 32 / 64 rows (a weight block's tiles on adjacent CTAs, the weights read from DRAM once), the same K splits and cluster sum; taken only where measured faster (fp8.cu mid_takes: always over the base; over P031 at ≤ 64 rows with split 1 or k/split ≥ 2048, at 65 … 128 rows with k/split ≥ 3072) — −1 … −36 µs a call (dsa.qgi 148.2 → 113.7 µs at 64 rows), a verify step est. −2.5 ms at B = 8, −0.6 at B = 16, 0 at B = 4
- 4-sequence verify steps (32 rows), bitwise: the large FP8 shapes at 17 … 32 rows on P200's kernel P220 (HCA wo_a / o_proj, DSA o_proj, dense: 171.8 → 155.4 µs a site), the DSA select of 17 … 64 verify rows on P046 with 1024-key splits P221 (32 rows 0.211 → 0.101 ms) — the 32-row step 123.7 → 120.7 ms (its MoE, 64 % of it, is at the bandwidth floor)
- DSpark verify by cost P143: the round-cost table measured at B = 8 / 16 (≈ 9.6K context; B 8 R 32 / 64 129.3 / 181.7 ms, B 16 R 64 / 96 / 128 184.2 / 231.0 / 255.8, the round's rest 17.0 / 26.6) instead of extended from B = 4
- the prefill rule: a prefill kernel may accumulate in its own order instead of the decode kernels' bits, keeping the reference's rounding points, determinism, batch and chunk-size invariance within prefill and the MoE combine's slot order; it is judged by the reference gate at the noise floor (gate.py --pf: rule off → on against the reference; engine/tests/pf_rule.py lists the rule's patches), not bitwise; decode / verify / draft steps keep their bits — P210 against the reference on ko_short / en_tools / doc_long (377 positions): KL(ref‖·) 0.645 off → 0.420 on, top-1 0.777 both
- prefill HCA attention as one online softmax over a row's keys P210 (prefill rule; 16-key tiles from key 0, no 256-key chunks, partials or merge; 4 producer warps dequantizing exactly into a 4-deep ring, setmaxnreg): a 2048-row call at 0 / 131K / 524K 1.06 → 0.95 / 4.48 → 3.30 / 16.2 → 10.85 ms; deterministic, chunk / lane invariant (bitwise), its error vs fp64 the current kernel's (rms ≤ 1.04×) — a 990K-token cold prompt 522.7 s (1,894 tok/s; 0.5.0 625.8 s for 995K), the next turn at 1M 9.0 s (10.8)
- server, host side: stream pushes on a pusher thread, flushed before every long engine call; GIL switch interval 0.5 ms; the loop guard incremental; an idle scheduler waits instead of polling; KV guard snapshots every 0.5 s; server.decode_chunk (0 = off: a new prompt's chunk read in pieces of ≥ 512 rows with decode rounds between, the same output) — host work a round at B 4 / 8 / 16 0.054 / 0.102 / 0.189 → 0.036 / 0.058 / 0.103 ms (sched_round.py, a fake engine)
- /metrics: spec_decode_num_drafts counts the sequence-rounds that verified at least one draft (vLLM's definition), not every sequence-round
- tools/tp2.sh: E55_GPU_LOCK=1 takes A's and B's GPU locks before either rank starts (rank 1 alone waited for B's, so the ranks could start apart)
